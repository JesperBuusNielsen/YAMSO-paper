\section{Technical Overview}
\label{sec:technical-overview}

\subsection{The ledger}
\label{sec:overview-ledger}

The ledger $\FLedger[\Pi]$ records setup, registrations, clock ticks, and
messages in one public list $L$.  A YASO protocol $\Pi$ specifies key
generation, the speaking schedule, and the parties' local algorithms.
Registration generates a public key $\pk$, used as the party identifier,
and retains its secret state inside the ledger.  This is UC bookkeeping
for protected local computation; it avoids returning the secret key as
an intermediate output.  Section~\ref{sec:yaso-syntax} gives the protocol
syntax, and Figure~\ref{fig:yaso-ledger} defines its execution.

There are two classes of parties.  Computation parties provide the
auxiliary work; each is independently corrupt at registration with
probability $p$.  Initially honest computation parties are protected
while silent and may be corrupted after speaking.  Application parties
provide inputs or receive outputs and may be corrupted at any time.
Corruption exposes all retained secrets, randomness, and computations.
Our construction uses $p<1/3$ and never reuses a party for a later role.

Each party may post at most once.  An honest posting is irrevocable and
cannot be overtaken through subsequent corruption.  At each tick, the
ledger freezes the public record and accumulated private inputs used by
that round's local computations.  The adversary chooses their order;
the ending tick executes any remaining eligible honest parties and
delivers the round's private outputs.  A silent input provider can first
receive its circuit and assignment, then supply an input and speak in a
later round.  Scheduling and silence are
specified precisely in Section~\ref{sec:ledger-execution}.

\subsection{The ideal functionality}
\label{sec:overview-functionality}

The intended task $\FMPC$ maintains an initially empty secret state.
In I/O round $s$, a public Boolean circuit computes
\[
  (\sigma_s,y_s,\phi_s)=F_s(\sigma_{s-1},x_s).
\]
Here $\phi_s$ is public, and a fixed rule chooses
$F_s=G(s,\phi_1,\ldots,\phi_{s-2})$.
Its public layout assigns an input string of specified length to each
input provider and one output bit to each output recipient.  These
application parties are the participants of the ideal task; computation
committees belong to its implementation.  Write
$\boldsymbol{\pid}_s=(\boldsymbol{\pid}^{\mathsf{in}}_s,
\boldsymbol{\pid}^{\mathsf{out}}_s)$ for the ordered input-provider and
output-recipient lists.  The circuit notification is
$(s,F_s,\boldsymbol{\pid}_s)$; a provider identifies its input index by
its position in $\boldsymbol{\pid}^{\mathsf{in}}_s$.

Inputs and recipient outputs remain private, while participation is
visible.  Missing inputs have the all-zero value of the prescribed
length.  The input commitment must match the protocol: an honest posting
fixes its contribution, whereas corruption before posting permits the
provider to change or omit it.  Corruption reveals the affected party's
retained inputs and already-determined outputs, including outputs pending
delivery.  The functionality determines outputs when inputs close and
delivers honest recipients' outputs at the later designated tick.

Section~\ref{sec:ideal-mpc} defines the reactive task and its
registration, announcement, input, and output interfaces.  The adversary
chooses when to proceed; the clock then fixes the input deadline and
output-delivery time.

Figure~\ref{fig:model-simulation} compares the ledger execution with its
ideal simulation.  On the left, the protocol algorithms provide setup
($\CRS$), key generation ($\Gen$), scheduling ($\Schedule$), and local
computation ($\ComputationStep$, $\ApplicationStep$);
Section~\ref{sec:yaso-syntax} gives their interfaces.
On the right, $\Announce$ fixes the circuit and participant assignments;
input providers receive their notification at $\ReadyTick_s$.
The command $\Proceed$ schedules the input window for the next tick.
The simulator uses $\CommitInput$ to fix an honest provider's already
selected input without learning it, and $\CorruptInput$ to supply a
corrupted provider's contribution.  Registration returns the NCE
ciphertext $\widetilde c$ and explanation information $\tau$, together
with a signing key $\sigsk$ and its generation tape $\rho_{\mathsf{sig}}$;
these let the simulator explain later corruptions.
Section~\ref{sec:mpc-execution} defines these commands, and
Section~\ref{sec:simulator} describes the simulation.

\subsection{Gadgets}
\label{sec:overview-gadgets}

We use an independent garbled circuit for each I/O round.  Its inputs
are public ciphertexts and keys; the private application computation
takes place inside the garbling.

\begin{description}
  \item[Public sampling.]
    Universal-sampler parameters $U$ let everyone derive the same public
    bundle
    \[
      \GarbledRound_s=\Sample^H(U,\SampleCircuit_s).
    \]
    Here $\SampleCircuit_s$ describes a distribution producing a garbling,
    its public keys, and encrypted information for the participants.
    The sampling coins and garbler's secrets are not revealed, so no
    participating party serves as the private garbler.
    Registered encryption keys used for these packets are called
    \emph{delivery keys}.  The description fixes them along with the
    circuit, role assignments, and a nonce.  Replacing a delivery key
    changes the sampled instance: in the universal sampler's ideal
    experiment, distinct descriptions receive independent samples.
    Honest parties act on the instance determined by the ledger.
    Figure~\ref{fig:distribution-circuit} specifies the distribution and
    its returned bundle.

  \item[Signed encrypted inputs.]
    The sample gives each provider a fresh input-encryption public key
    and embeds the matching secret key inside the garbled circuit.
    The provider encrypts its private input string and signs the
    ciphertext for this round and sample.  The first valid signed record
    before the deadline fixes its public input record; absence or failed
    decryption means the all-zero application input.  Thus ciphertext
    bits are public, but their plaintext is used only inside the circuit.
    Non-committing encryption supports explaining the retained encryption
    randomness when an honest sender is later corrupted.
    Figure~\ref{fig:signed-encrypted-inputs} gives the submission and
    selection rules; Figure~\ref{fig:round-circuit} gives the decryption
    and default behavior.

  \item[Conditional label release.]
    For each garbled input wire, two disjoint committees hold robust
    sharings of its two labels.  The sampler encrypts each share under
    its member's delivery key.  Once the complete public input is fixed,
    the committee for each selected bit releases its label: honest
    members post their secret keys, from which everyone recovers their
    shares.  Robust reconstruction tolerates faulty or missing shares
    within the threshold.  The other committee's honest members remain
    silent, protecting the unused label even after all speakers are
    corrupted.  This is where choosing not to speak provides secrecy.
    Receiver non-committing encryption and share completion allow the
    proof to explain these deliveries consistently with labels fixed
    later.  Figures~\ref{fig:conditional-release}
    and~\ref{fig:garbled-input-release} define the release mechanism.

  \item[A delayed shared coin.]
    Before releasing the nonce $Q_s$, the protocol fixes every other
    field of $\SampleCircuit_s$.  A separate universal sample shares
    $Q_s$ among a dedicated committee using the same encrypted-sharing
    mechanism.  The hidden nonce makes the final sampling description
    unpredictable before release; robust reconstruction prevents corrupt
    members from steering it by withholding shares.  This protects against
    advance sampling of the eventual
    instance, even when participants' keys were registered long ago.
    The coin sub-protocol is in Figure~\ref{fig:shared-coins}.

  \item[Encrypted state between independent garblings.]
    The sample for round $s$ publishes a fresh state-reception key
    $\statepk_s$ and embeds its secret key in the garbled circuit.
    After decrypting the incoming state and computing $F_s$, the circuit
    outputs
    \[
      c_s=\PKE.\Enc(\statepk_{s+1},\sigma_s;\rho_s).
    \]
    The successor decrypts this ciphertext inside its own garbling.
    Evaluation also reveals the public application output $\phi_s$.
    No speaking intermediary holds the state, and neighboring garblings
    need no shared wire labels.  The incoming ciphertext and successor
    public key are late public inputs, so the current garbling can be
    prepared before they exist.  Label committees restrict evaluation
    to their ledger-determined values.
    Figure~\ref{fig:round-circuit} specifies this augmented plaintext
    circuit; Figure~\ref{fig:distribution-circuit} samples its keys and
    hidden randomness.

  \item[Private outputs from public evaluation.]
    The sampled circuit masks each output bit as $z_i=y_i\oplus r_i$
    using an independent uniform pad $r_i$.
    Its sample also contains an RNCE encryption of the pad $r_i$ under
    the recipient's delivery key.  Everyone can evaluate and decode the
    garbling, while the recipient privately recovers its output without
    speaking.  Figure~\ref{fig:distribution-circuit} prepares the pad
    ciphertexts, and Figure~\ref{fig:protocol-steps} specifies recovery.
\end{description}

\subsection{The construction}
\label{sec:overview-construction}

The protocol assigns unused registered parties to application roles and
committees in registration order, waiting for enough keys when necessary.
Keys may be registered in advance; assignment is permanent even for
parties that remain silent.  An assigned input provider receives its
circuit and role at the following tick, before its input-posting round.
Figure~\ref{fig:role-allocation} gives the allocation rule.

After preparing round 1, the protocol repeats four phases: prepare the
successor, collect the current round's signed encrypted inputs, release
the selected labels, and evaluate and deliver outputs.  Each phase
occupies one ledger round.  The input-posting deadline fixes the public
string whose labels will be released.  Everyone then derives the same
garbled evaluation result; no additional party posts the state ciphertext,
masked outputs, or public output $\phi_s$.
Figure~\ref{fig:protocol-schedule} specifies the start
ticks and public reconstruction, and Figure~\ref{fig:protocol-steps} gives
the party algorithms.

Preparing the successor needs its circuit description and participant
keys, but neither its private inputs nor the current round's outgoing
state ciphertext.  The rule $F_{s+1}=G(s+1,\phi_1,\ldots,\phi_{s-1})$
provides this lookahead without preparing the entire future computation.
Applications whose next circuit uses their most recent public output
can insert identity circuits in the even rounds, as described in
Section~\ref{sec:reactive-task}.
Each sample has bounded size, while setup leaves the total number of I/O rounds
unfixed.
