\section{Technical Overview}
\label{sec:technical-overview}

\subsection{The ledger}
\label{sec:overview-ledger}

The ledger $\FLedger[\Pi]$ records setup, registrations, clock ticks, and
messages in one public list $L$.  A YASO protocol $\Pi$ specifies key
generation, the speaking schedule, and the parties' local algorithms.
Registration generates a public key $\pk$, used as the party identifier,
and retains its secret state inside the ledger.  This is UC bookkeeping
for protected local computation; it avoids returning the secret key as
an intermediate output.  Section~\ref{sec:yaso-syntax} gives the protocol
syntax, and Figure~\ref{fig:yaso-ledger} defines its execution.

There are two classes of parties.  Computation parties provide the
auxiliary work; each is independently corrupt at registration with
probability $p$.  Initially honest computation parties are protected
while silent and may be corrupted after speaking.  Application parties
provide inputs or receive outputs and may be corrupted at any time.
Corruption exposes all retained secrets, randomness, and computations.
Our construction uses $p<1/3$ and never reuses a party for a later role.

Each party may post at most once.  An honest posting is irrevocable and
cannot be overtaken through subsequent corruption.  At each tick, the
ledger freezes the public record and accumulated application inputs used by
that round's local computations.  The adversary chooses their order;
the ending tick executes any remaining eligible honest parties and
delivers the round's private outputs.  A silent input provider can first
receive its circuit and assignment, then supply an input and speak in a
later round.  Scheduling and silence are
specified precisely in Section~\ref{sec:ledger-execution}.

\subsection{The ideal functionality}
\label{sec:overview-functionality}

The intended task $\FMPC$ maintains an initially empty secret state.
In I/O round $s$, provider $a$ supplies an input pair
$x_{s,a}=(\xsec_{s,a},\xpub_{s,a})$.  The secret components form
$\xsec_s$, and a public Boolean circuit computes
\[
  (\sigma_s,\ysec_s,\ypub_s)=F_s(\sigma_{s-1},\xsec_s).
\]
Here $\ysec_s$ is the vector of private recipient outputs and $\ypub_s$
is one common public output string.  A fixed rule selects the circuit from
preceding public inputs and outputs:
\[
  F_s=G\bigl(s,(\xpub_t,\ypub_t)_{1\leq t\leq s-2}\bigr),
\]
where $\xpub_t$ lists the accepted public input components in provider
order.  The circuit's public layout assigns a secret input string of
specified length to each provider and one private output bit to each recipient.
These application parties are the participants of the ideal task;
computation committees belong to its implementation.  Write
$\boldsymbol{\pid}_s=(\boldsymbol{\pid}^{\mathsf{in}}_s,
\boldsymbol{\pid}^{\mathsf{out}}_s)$ for the ordered input-provider and
output-recipient lists.  The circuit notification is
$(s,F_s,\boldsymbol{\pid}_s)$; a provider identifies its input index by
its position in $\boldsymbol{\pid}^{\mathsf{in}}_s$.
The application call $\Input((s,a,x))$ specifies the I/O round, provider
index, and pair $x=(\xsec,\xpub)$.

Secret inputs and recipient outputs remain private, while participation
and public input components are visible.  Missing submissions have an
all-zero secret component of the prescribed length and an empty public
component.  The input commitment must match the protocol: an honest posting
fixes its contribution, whereas corruption before posting permits the
provider to change or omit it.  Corruption reveals the affected party's
retained inputs and already-determined outputs, including outputs pending
delivery.  The functionality determines outputs when inputs close.
At the designated tick it delivers each due bit or circuit notification
$v$ in registration order.  It sends $v$ directly to an honest pid.
At a corrupted pid's turn it sends $(\Deliver,r,\pid,v)$ to the adversary.

Section~\ref{sec:ideal-mpc} defines the reactive task and its
registration, announcement, input, and output interfaces.  The adversary
chooses when to proceed; the clock then fixes the input deadline and
output-delivery time.

Figure~\ref{fig:model-simulation} compares the ledger execution with its
ideal simulation.  On the left, the protocol algorithms provide setup
($\CRS$), key generation ($\Gen$), scheduling ($\Schedule$), and local
computation ($\ComputationStep$, $\ApplicationStep$);
Section~\ref{sec:yaso-syntax} gives their interfaces.
On the right, $\Announce$ fixes the circuit and participant assignments;
input providers receive their notification at $\ReadyTick_s$.
The command $\Proceed$ schedules the input window for the next tick.
The simulator uses $\CommitInput$ to fix an honest provider's already
selected input without learning its secret part, and $\CorruptInput$ to
supply a corrupted provider's contribution.  Registration returns the NCE
ciphertext $\widetilde c$ and explanation information $\tau$, together
with a signing key $\sigsk$ and its generation tape $\rho_{\mathsf{sig}}$;
these let the simulator explain later corruptions.
Section~\ref{sec:mpc-execution} defines these commands, and
Section~\ref{sec:simulator} describes the simulation.

\subsection{The construction}
\label{sec:overview-construction}

Each I/O round uses an independently sampled garbling.  To carry private
state from round $s$ to round $s+1$, we prepare the successor before
evaluating the current circuit.  The successor's sample publishes a
state-reception key $\statepk_{s+1}$ and embeds the matching decryption
key in its garbling.  Round $s$ takes this public key as an input and
encrypts its outgoing state $\sigma_s$ under it.  The public history
through round $s-1$ already determines $F_{s+1}$.  This one round of
lookahead lets us prepare the successor before $\sigma_s$ exists.
Let $c_s$ denote the encrypted state, $\InputRecords_s$ the providers'
ciphertext records, and $\boldsymbol r_s$ the vector of output pads.
The plaintext circuit of Figure~\ref{fig:round-circuit} computes
\[
 C_s(c_{s-1},\InputRecords_s,\statepk_{s+1})
   = (c_s,\;\ysec_s\oplus\boldsymbol r_s,\;\ypub_s).
\]

\paragraph{Preparing a round.}
Everyone evaluates $\Sample^H(U,\SampleCircuit_s)$ with the public
sampler parameters $U$.  The resulting bundle $\GarbledRound_s$ gives
everyone the same garbling, public keys, and encrypted packets for the
participants while keeping the garbler's coins hidden.  The sampling description fixes $F_s$, the assigned
parties, and the registered encryption keys for their packets (their
\emph{delivery keys}).  In the sampler's ideal experiment, substituting
a delivery key changes which description's random tape is used.  These
tapes are independent across distinct descriptions.  A fresh committee releases
the nonce $Q_s$ only after the other fields are fixed, keeping the
exact description unpredictable to the adversary until release.
Figures~\ref{fig:shared-coins} and~\ref{fig:distribution-circuit}
give the coin and the sampling circuit.

\paragraph{Selecting the input.}
The sample supplies a fresh public input-encryption key for each provider.
The provider encrypts its secret input under that key and signs the
ciphertext together with its public input for this round and sample.
The first valid record before the deadline fixes both.  The public
component enters the history for $G$ directly.
Figure~\ref{fig:signed-encrypted-inputs} gives the selection and default rules.

At the deadline all three inputs to $C_s$ are public.  Consider one
wire $w$ whose ciphertext bit is $1$.  The sampler has shared
$L_{w,0}$ and $L_{w,1}$ among two disjoint committees and encrypted
each share under its member's delivery key.  Honest members of the
$1$-committee now post their decryption keys.  Anyone can recover
their shares and reconstruct $L_{w,1}$.  Honest members of the
$0$-committee stay silent and are never reassigned.  Even after every
speaker is corrupted, only the initially corrupt members of that
committee can expose their shares.  With overwhelming probability these
are too few to recover $L_{w,0}$.  Applying this rule to every input
wire releases one encoding of the ledger-determined input
(Figure~\ref{fig:garbled-input-release}).

\paragraph{Evaluating and continuing.}
Everyone evaluates the garbling on that encoding.  Inside the circuit,
decryption recovers the incoming state and the providers' secret inputs
for $F_s$.  The successor takes $c_s$ as its first input.
Each private recipient unmasks its bit using
the pad encrypted to it in the sample, without speaking.  The common
output $\ypub_s$ joins the public inputs in the history for choosing
later circuits.  Each round uses the same parameters $U$, so setup
need not fix the number of rounds.
Figures~\ref{fig:protocol-schedule} and~\ref{fig:protocol-steps} give
the schedule and party algorithms.
