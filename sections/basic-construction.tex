\section{The Basic Finite Construction}
\label{sec:basic-construction}

We illustrate the central idea for one evaluation of a public Boolean circuit
$F$. The input providers are named application parties and the output is
public. Computation roles are assigned to registered computation keys by a
public rule. The construction uses the ledger only through the generic API of
\cref{sec:model}; all garbling, role assignment, encryption, and message
validation described below are protocol operations.

\subsection{Public role layout and derived setup}

Fix a ledger prefix $L_0$ containing the registered input providers and at
least $2mk$ computation keys, where $m$ is the number of input wires. For
each wire $w$, the public role map selects two disjoint size-$k$ committees
$C^w_0$ and $C^w_1$ from the computation-key indices. All $2m$ committees
are mutually disjoint. Their subscripts are merely public \emph{branch
indices}; they do not yet denote semantic input bits.

For concreteness, the protocol may choose the generic setup distribution so
that $\mathsf{crs}$ contains a universal-sampler parameter $U$. From
$(F,L_0)$ all parties form the same finite sampling description $d$ and
compute $p_d=\mathsf{Sample}(U,d)$. This public derived object is what we
informally mean when saying that a garbled circuit or ciphertext is ``on the
ledger.'' It need not be appended to $L$: every party recomputes the same
object from the CRS and the canonical public prefix. Only the messages---in
particular, disclosed secret keys---are appended to $L$.

The sampled distribution garbles $F$, producing a public garbled circuit
$\widetilde F$, input-label pairs $(K^w_0,K^w_1)$, and public output-decoding
information. For every input wire $w$, it also samples independent activation
tokens $(T^w_0,T^w_1)$ and a random permutation $\pi_w$ of $\{0,1\}$. The
label $K^w_b$ is verifiably $(t+1)$-out-of-$k$ shared among the public
committee $C^w_{\pi_w(b)}$, where $t=\lfloor(k-1)/3\rfloor$.

For each member with public key $pk_i\in C^w_{\pi_w(b)}$, the public object
contains a ciphertext
\[
  D_i=\mathsf{Enc}_{pk_i}
      (w,T^w_b,\mathsf{share}_{i,b},\mathsf{verification\ data}).
\]
The public object similarly contains, under the registered key of the
application party providing wire $w$, an encrypted packet with the two tokens
and their semantic mapping. The permutation and the semantic bit attached to
a public branch committee are not output in the clear. Thus committee
membership may be public without revealing whether that committee represents
zero or one.
No computation key is used in more than one role.

The fixed description of $\mathsf{WhosTurn}$ supplied at ledger initialization
returns $\bot$ until the canonical prefix $L_0$ exists and then schedules the
input-provider keys and computation-role keys in a fixed canonical order.
Registration itself contains no role argument.

\subsection{Input activation}

When the registered key $pk_P$ of the provider for wire $w$ is scheduled,
an honest provider with input $x_w$ supplies a protected algorithm $A_{w,x_w}$
to the ledger. The algorithm derives the public setup object, decrypts the
provider packet using $sk_P$, and returns the tagged token $T^w_{x_w}$. The
ledger signs and appends this output without revealing $sk_P$, the other
token, or the input-dependent algorithm.

A corrupt provider may put any string in its turn, and the ledger records it
unchanged. The protocol treats a correctly tagged single value as the
activation string for $w$; an ambiguous or malformed entry causes that input
instance to abort. No reset attack is possible at the ledger level because
the provider key is spent after this turn.

\subsection{Conditional key release and evaluation}

Each computation member is subsequently scheduled once. Its honest protected
algorithm derives $D_i$, decrypts it with $sk_i$, and compares the enclosed
token with the activation entry for wire $w$. On a match it returns $sk_i$;
otherwise it returns $\bot$. Consequently the active committee reveals its
secret keys, while every honest member of the sibling committee produces only
a $\mathsf{NoMsg}$ timeout and keeps its key hidden forever.

The ledger performs no validation. Protocol observers ignore a purported
key unless $\mathsf{KeyMatch}(pk_i,sk_i)$ holds, decrypt $D_i$ themselves,
and reject malformed shares using the public verification data. Conditioned
on $\mathsf{Good}$, the active committee contains enough honest parties to
reveal at least $t+1$ valid shares despite corrupt withholding. Everyone can
therefore reconstruct exactly one active label $K^w_{x_w}$ for each honest
input wire. These labels, like $\widetilde F$ itself, are public values
derived from the common ledger view rather than additional ledger entries.
All parties evaluate $\widetilde F$ and decode the public output.

\subsection{Why complete exposure need not be fatal}

Publishing $sk_i$ exposes the selected role's entire secret state because
that state is exactly what $sk_i$ decrypts from public $D_i$. The exposed
share belongs to a label that is reconstructed publicly anyway. It gives no
share of the disjoint sibling label. In the sibling committee, at most $t$
members are corrupt on $\mathsf{Good}$, while every honest member remains
silent; threshold privacy therefore protects the unselected label.

The random permutation $\pi_w$ is necessary in the present public-role
model. Without it, observing which public committee releases its keys would
directly reveal the input bit. With the permutation hidden inside the sampled
and encrypted setup, public branch selection has no fixed semantic meaning;
the remaining dependence on the input is handled by garbling privacy.

If an honest input provider is corrupted after its turn, its retained state
and both tokens may become known, and the target functionality correspondingly
reveals its input to the simulator. The adversary still cannot replace the
already final ledger entry or obtain a second turn. If the provider was
corrupt before its turn, it controls that input message and may force the
protocol to abort, exactly as allowed by the target functionality.

This is still a blueprint rather than a theorem. A complete proof must
combine universal-sampler security, multi-user encryption, hiding and
robustness of the verifiable sharing, garbling privacy, the binomial
good-committee bound, and adaptive corruption of the named input providers.
In particular, the verification data must not reveal the hidden semantic
permutation, and the simulator must explain ciphertexts both for initially
corrupt computation keys and for keys publicly disclosed by the selected
committee.

\paragraph{A gate-by-gate variant.}
For intuition, garbling can be replaced by an expensive
information-theoretic construction. For every NAND gate and public structural
branch corresponding to a pair of input tokens, a separate computation
committee holds shares of the corresponding output token. Only the committee
whose encrypted activation data matches the public inputs reveals its keys.
This makes the role of silence especially transparent, at the cost of a large
setup and many registered computation parties.
